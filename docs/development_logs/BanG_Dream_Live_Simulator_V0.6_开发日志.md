## 三、本版本新学到的知识

### 1. Object State（对象状态）

对象不仅可以保存静态数据，也可以保存运行过程中的变化。

Character 从单纯的数据结构变成具有状态的对象。

### 2. Object Reference（对象引用）

理解变量保存的是对象引用。

修改对象属性后，其他地方访问同一个对象可以获得变化后的状态。

### 3. Method 数据传递

发现局部变量无法跨 method 使用。

解决方式：

将长期需要的数据保存到对象属性中，而不是依赖局部变量。

### 4. Class 职责划分

Character： - 保存成员信息 - 保存自身状态 - 修改自身状态

Live： - 管理演出流程 - 触发随机事件 - 计算最终结果

random_events： - 提供随机结果

## 四、Bug / 问题记录

### Bug #01：随机成员无法影响最终分数

现象：

随机事件可以显示成员状态变化，但是最终评分没有变化。

原因：

随机事件中的成员变量属于局部变量，函数结束后无法被其他 method 使用。

解决：

随机事件修改 Character 对象状态，评分时重新读取成员状态。

学到：

系统状态应该保存于对象内部。

------------------------------------------------------------------------

### Bug #02：随机事件生成多次

现象：

如果计算分数时再次调用随机事件，会导致结果不一致。

原因：

随机过程和计算过程混合。

解决：

随机事件只执行一次，后续读取结果。

学到：

随机事件应该产生结果，而不是重复生成。

------------------------------------------------------------------------

### Bug #03：状态数据类型不统一

现象：

初始状态和计算状态类型不同。

原因：

字符串和浮点数混用。

解决：

统一使用浮点数表示倍率。

## 五、本版本设计决定

评分时遍历当前乐队成员状态，计算整体倍率。
