## 三、本版本新学到的知识

### 1. Module
一个 `.py` 文件本身就是一个 Python 模块。

### 2. `import`
不同模块之间通过导入使用彼此的类、函数或数据。

### 3. 两种导入方式
- `import 模块` → 使用 `模块.名字`
- `from 模块 import 名字` → 直接使用 `名字`

### 4. 命名空间
一个模块中的名字不会自动出现在另一个模块中。

### 5. `__name__` 与 `"__main__"`
直接运行文件时，`__name__ == "__main__"`；被其他模块导入时不是。

### 6. `__pycache__`
Python 导入模块时会生成字节码缓存，可删除，也可通过 `.gitignore` 忽略。

### 7. Git 基础
学习了：
- `git init`
- `git status`
- `git add`
- `git commit`
- `git log`
- `git diff`
- `git push`

### 8. GitHub
Git 负责本地版本控制，GitHub 用于保存远程仓库。

## 四、Bug / 问题记录

### Bug #01：Git 初始化到了错误目录

**现象：** V0.1～V0.5 全部被 Git 标记。

**原因：** 在项目总目录执行了 `git init`。

**解决：** 删除错误目录中的 `.git`，只在 V0.5 目录重新初始化。

**学到：** Git 管理范围由仓库根目录决定。

---

### Bug #02：导入模块后无法直接使用类名

**现象：** `import class_set` 后直接写 `Band(...)` 无法使用。

**原因：** 导入整个模块后，类仍属于该模块命名空间。

**学到：** `import 模块` 与 `from 模块 import 名字` 的使用方式不同。

---

### Bug #03：拆分文件后出现名字找不到

**现象：** `bands`、`Live` 等名字在 `main.py` 中无法直接使用。

**原因：** 名字定义在其他模块中，没有正确导入。

**学到：** 写代码前先确认“这个名字定义在哪个模块”。

---

### Bug #04：import main 时仍会执行代码

**现象：** 被导入时仍可能输出标题或启动部分流程。

**原因：** 可执行代码放在文件顶层。

**解决：** 将程序启动流程放入 `if __name__ == "__main__":`。

**学到：** 模块被导入和模块被直接运行是两种不同状态。
